Hellmaker

Custom C++ engine for Death's Refrain — Team Infernumb, Year 2. Engine debugger and editor tooling.

Hellmaker is the in-house engine that runs Death's Refrain: a static Engine library, an ImGui Editor, and a Sandbox game executable. Technical Lead: Loh Boon Cheong, Timothy. I built the shared debugger and the editor UI that the team used to iterate levels and assets without a full rebuild for every change.

Debugger

I implemented Hellmaker's global debug layer, used by Engine, Editor, and Sandbox. Logs run from trace through critical, can target console, file, or both, and keep a ring buffer of recent messages. Init, shutdown, and crash helpers take a custom reason so a gameplay fault and an editor fault land in the same pipeline (spdlog).

On top of that I wrote the editor Debug Console: an ImGui window that streams those logs live and lets us filter what the engine is doing without attaching a second logger.

Editor (Dear ImGui)

I wrote the editor GUI manager: it wraps ImGui so other systems can open windows without depending on ImGui types, and it drives layout — docking, FPS, editor mode, and return to the project launcher.

I authored the asset browser (Timothy contributed a smaller share, including ImGuiFileDialog integration). From the browser, assets can be dropped onto the game view; I implemented spawn-at-mouse so a dropped file becomes a GameObject at the cursor. The game view itself is shared with Alfred Lo and Timothy (render and gizmos). Together, that path is how a room was assembled in the editor instead of in C++.

How it supported the game

Death's Refrain is authored as data on this runtime. The debugger, console, and asset browser were the loop I used as Design Lead: inspect what the engine was doing, pick an asset, place it, and keep going. Mechanics, Lua, and integration are on the Death's Refrain page.
